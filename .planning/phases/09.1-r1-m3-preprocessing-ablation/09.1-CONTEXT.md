<domain>
## Phase Boundary

This phase delivers an empirical answer to AIChE reviewer R1-M3 ("the combination of log-returns and Lambert W transformation appears to strip much of the temporal structure from the original signal"). It does so by running a **controlled three-pipeline ablation** in which the only variable is the data transformation. Architecture, hyperparameters, optimizer, epochs, and seed sets are held identical across pipelines so any difference in OD-scale fidelity is attributable to the transformation.

**In scope:**
- Implementing three forward/inverse preprocessing pipelines as composable, pure functions in `revision/core/preprocessing.py` (Phase 9 already established the module contract — the four `NotImplementedError("Phase 09.1")` stubs are this phase's slot to fill).
- Running ≥5 seeds × 3 pipelines on local Mac statevector simulator (analytic, no shot noise).
- Computing OD-scale fidelity metrics (PDF/CDF, Q-Q, ACF, DTW) and lightweight TSTR (small LSTM forecaster).
- Producing six figures, a long-form `metrics.csv`, and a `summary.md` that answers four named rebuttal questions.

**Out of scope (other phases own these):**
- Full TSTR / predictive / discriminative score suite across all baselines → Phase 11 (EVAL-01..04).
- Shot-noise and noise-model sweeps → Phase 12 (SENS-01, SENS-02).
- Classical WGAN-GP / VAE / AR baseline comparison → Phase 10 (BASE-01..03).
- Manuscript integration of `summary.md` into the "Preprocessing Rationale and Ablation" subsection → Phase 14 (PAPER-04).

**Why this phase exists separately from Phase 9 / 10 / 11:** R1-M3 is a single reviewer item with a clear empirical test (does OD-scale ACF survive each transformation?). Bundling it into the broader baseline or utility phases would dilute the head-to-head transformation comparison. The user inserted this phase as 09.1 (URGENT) to front-load the rebuttal evidence and to lock in a recommended pipeline before Phase 10+ commit to a specific transformation.

</domain>

<decisions>
## Implementation Decisions

### Pipelines (LOCKED — from spec)

- **D-09.1-01:** Three pipelines, no more no less. A = raw normalized OD via min-max to [0,1]; B = log-returns only with standardization + cumulative integration from known starting OD on inverse; C = log-returns + Lambert W (Phase 9's existing differentiable pair).
- **D-09.1-02:** Each pipeline is a `forward_X` / `inverse_X` pair in `revision/core/preprocessing.py`. Phase 9 already locked the module location (D-06/D-07) and re-exports `forward_lambert` / `inverse_lambert` from `data.py`. Pipelines A and B must be NEW implementations; C reuses Phase 9's pair plus the log-return / standardization layer.
- **D-09.1-03:** Round-trip sanity test is a hard gate: `inverse(forward(x)) ≈ x` to within float epsilon on a real OD trajectory, max abs error printed. Pipeline C's full-pipeline round-trip target is ≤ 1e-6 (consistent with Phase 9 EVAL-06 `full_pipeline` tolerance).

### Training conditions (LOCKED — from spec)

- **D-09.1-04:** Identical circuit architecture, hyperparameters (N_CRITIC=9, λ=2.16, LR_CRITIC=1.8046e-05, LR_GENERATOR=6.9173e-05, Adam betas), optimizer, schedule, and seed set across all three pipelines. The only variable is the transform.
- **D-09.1-05:** Statevector simulator, analytic expectation values, no shot noise. Phase 12 owns shot-noise sweeps.
- **D-09.1-06:** ≥5 random seeds per pipeline. Spec acknowledges compute budget — 3 pipelines × 5 seeds × full epoch budget ≈ 15× single-run cost. Strategy: smoke test (1 seed, small epoch count) → 3 seeds full → +2 seeds optional based on initial spread.
- **D-09.1-07:** Save all generated samples (N_synth ≈ 10 × N_real per seed) as `.npy` or `.parquet` for later reuse by Phase 11 / 14.
- **D-09.1-08:** All hyperparameters and seeds logged to a YAML run config alongside results.

### Evaluation (LOCKED — from spec)

- **D-09.1-09:** Primary metrics computed on OD scale after inverting transforms: trajectory overlays, PDF/CDF, Q-Q, ACF (mean ± 1σ band across samples), DTW distance distribution.
- **D-09.1-10:** Utility check is a **lightweight TSTR**: small LSTM forecaster trained on synthetic OD, evaluated on held-out real, reporting MSE and R². This is not the full Phase 11 TSTR — it's a sanity scaffolding to detect catastrophic regressions.
- **D-09.1-11:** Supplementary ACF and Q-Q in *transformed* space for pipelines B and C, to expose the relationship between transformed-space and OD-space metrics. Pipeline A has no transformed space distinct from OD.
- **D-09.1-12:** Pipeline C must reproduce v1.1 published log-return EMD within 1–2% — sanity check that the ablation harness preserves baseline behavior.

### Output structure (LOCKED — from spec)

- **D-09.1-13:** Results root is `revision/results/transform_ablation/`. Inside it: `figures/` (6 PNGs), `metrics.csv` (long-form), `summary.md`, `runs/<pipeline>/<seed>/` (checkpoints, samples, config YAML).
- **D-09.1-14:** `metrics.csv` schema is **long-form**: columns = `pipeline, seed, metric_name, scale, value`. This shape supports easy groupby in pandas without one-column-per-metric explosion.
- **D-09.1-15:** `summary.md` must explicitly answer four named questions (Q1: does A train successfully with preserved ACF? Q2: does B match/exceed A on OD-scale? Q3: does C outperform B? Q4: is OD-scale ACF preserved across all three?) — one numbered paragraph per question, plus a recommendation paragraph at the end.

### Code conventions (LOCKED — from spec)

- **D-09.1-16:** Match the existing `revision/core/` package layout — no duplicated training code. Reuse `revision/core/training.py`'s training loop.
- **D-09.1-17:** Pipelines live in `revision/core/preprocessing.py` (filling the Phase 9 `NotImplementedError("Phase 09.1")` stubs). Forward/inverse are pure functions; no class state.
- **D-09.1-18:** Use `np.random.default_rng(seed)` for any new numpy randomness — do not call `np.random.seed`. Phase 8/9 codebase already follows this convention.
- **D-09.1-19:** Type hints throughout; verbose where it aids reading. Notebooks plot and orchestrate; `revision/core/` contains logic, not plot helpers.

### Claude's Discretion (explicit grants)

The PRD covers WHAT to deliver in detail. The following are explicitly the planner's call:

- **CD-1:** How to factor training-loop orchestration across pipelines — single notebook with a pipeline-loop, or three sibling notebooks, or a CLI script. Pick what minimizes code duplication while keeping per-seed results auditable.
- **CD-2:** Specific epoch count for smoke test vs full run. Spec says "small epoch count" for smoke without naming a number; planner should propose a defensible figure (suggest ~50–100 epochs for smoke given v1.1 used 2000 full).
- **CD-3:** Wave grouping. Pipelines A and B preprocessing implementations are independent; C reuses Phase 9. Smoke test, full multi-seed runs, and analysis/figure generation form natural sequential gates.

- **CD-5:** How to seed the cumulative-integration step in Pipeline B's inverse (use real-data starting OD vs sampled, batched vs per-window). Document the choice and verify it doesn't bias the OD-scale metrics.

<specifics>
## Specific Ideas

### Compute budget reality
3 pipelines × ≥5 seeds × 2000 epochs ≈ 15× v1.1 single-run cost. v1.1 single-seed wall time was "hours" — this phase is **days**. The planner should:
- Size the smoke test to be **fast** (~50–100 epochs, 1 seed) — used to catch broken inverse transforms, NaNs, or flat outputs before launching the full run.
- Default to 5 seeds, with the +2 seeds gate based on observed inter-seed spread after the first 5 complete.
- Consider whether full v1.1 epoch count (2000) is needed for the comparison, or whether a reduced epoch count (e.g., 1000) gives the same qualitative answer at half the wall time. If the planner picks a reduced count, document it as a Phase 09.1-specific decision.

### Pipeline B mechanic detail
Cumulative integration `OD_t = OD_0 * exp(sum_{i=1..t} r_i)` on inverse. The starting OD `OD_0` choice matters — using the real-data starting OD per-window keeps the OD trajectories anchored to realistic values; using a sampled starting OD lets the synthetic distribution start from a learned distribution of initial conditions. The PRD doesn't dictate which; planner picks and documents.

### Pipeline A scale handling
Min-max normalization to [0, 1] is well-defined per-trajectory or globally. Phase 9 dataset_stats.md confirms a single OD range (one campaign). Global min/max is the natural choice — document and verify it doesn't clip outliers.

### ACF computation
"Mean ACF across samples with ±1σ band" — the spec is asking for a per-sample ACF, then aggregating across the ensemble. Existing `revision/core/eval.py` likely has ACF — confirm before writing new code.

### Figure quality
Figures will go in the manuscript supplementary at minimum, possibly main text. Resolution, font sizes, and color choices should be journal-quality from the start, not afterthoughts. The existing `revision/` notebooks have a plotting style — match it.
