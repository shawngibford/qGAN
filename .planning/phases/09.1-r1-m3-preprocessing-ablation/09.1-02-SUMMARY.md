## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4 - Architectural, user-approved] Redefined Pipeline C parity gate from absolute-EMD threshold to structural-evidence gate**

- **Found during:** Task 2 (smoke notebook initial execution)
- **Issue:** The plan's literal 2 % absolute-EMD parity gate is physically incoherent. `parity_check.json::post.emd = 0.12048789` was measured against a converged 2000-epoch checkpoint's forward pass. Comparing that to a 100-epoch fresh-init run is comparing converged-model output to under-trained output. v1.1's converged log-return samples have std ≈ 0.104 vs real std 0.218 (PROJECT.md). Fresh 100-epoch samples cluster near zero (std ≈ 0.017), producing a SMALLER EMD against real (0.0155), not a match to 0.12049. This is not a regression — it is the expected behavior of an under-trained model.
- **Confirming evidence in the plan itself:** Task 2 step 5's own stated intent reads:
  > "what we are gating is that the *harness is structurally correct* (data loads identically, models build identically, training-loop calls identically)"
  The 2 % EMD threshold contradicts that intent; the structural signals (NaN-free, non-flat, equal wall-time) are what actually catch a harness-breaking change cheaply in minutes.
- **Confirming evidence from prior plan:** Pipeline C's code-path identity vs v1.1 is independently verified by plan 09.1-01's ABL-01 round-trip (`max_abs_err = 4.44e-16`, well below tolerance). That round-trip, not the smoke EMD comparison, is the actual proof of Pipeline C identity.
- **Fix:** Modified `04_ablation_smoke.ipynb` cells 5, 6, 7, 10, 11, 13:
  - Cell 5 (NaN/flat gate): `structural_pass` per pipeline now = `not has_nan AND not has_inf AND flat_fraction < 0.01 AND shape_ok`. Tightened flat threshold from 10 % to 1 %.
  - Cell 6 (markdown): renamed section to "Pipeline C parity comparison — INFORMATIONAL ONLY"; documented the rationale above.
  - Cell 7 (parity computation): retained EMD calculation for auditability but REMOVED the `pass` field tied to the 2 % threshold. The dict is now `parity_info` with informational fields only.
  - Cell 10 (markdown): rewrote gate-definition section to match the new structural-evidence approach.
  - Cell 11 (smoke_check.json writer): `structural_pass` and `all_passed` now derived from genuine structural signals + a `parity_note` field referencing the ABL-01 round-trip as the actual identity proof.
  - Cell 13 (final message): simplified GO/NO-GO branches; removed the now-dead "SMOKE PARTIAL" branch.
- **Files modified:** `04_ablation_smoke.ipynb`, `results/transform_ablation/smoke_check.json`
- **Verification:** `python3 -c "import json; d=json.loads(open('results/transform_ablation/smoke_check.json').read()); assert d['structural_pass'] is True and d['all_passed'] is True; print('PASS')"` → PASS
- **Committed in:** `0882d9a` (Task 2 commit, with full rationale in commit message)

**2. [Rule 2 - Missing Critical] Notebook idempotency on re-execution**

- **Found during:** Task 2 finalization (after gate redefinition required notebook re-execution against existing 100-epoch checkpoints)
- **Issue:** Original cell 3 always re-invoked `run_ablation.py` regardless of whether `samples.npy` existed. Re-running for the gate fix would have wasted ~80 s of training compute.
- **Fix:** Cell 3 now checks `samples_path.exists()` per pipeline and short-circuits training if present. Wall-time is preserved across re-executions by reading prior `timings_seconds` from the existing `smoke_check.json`.
