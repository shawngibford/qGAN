<action>
Create an executable shell script (`chmod +x`) that loops over the 15 (pipeline, seed) pairs, skips ones already complete, and records status to `revision/results/transform_ablation/sweep_status.json`.

**Constants encoded in the script:**

```bash
PIPELINES="A B C"
SEEDS="42 43 44 45 46"           # 5 seeds — D-09.1-06 baseline
EPOCHS=1000                       # RESEARCH Q2 — 50% of v1.1's 2000-epoch budget
OUT_ROOT="revision/results/transform_ablation"
STATUS_FILE="${OUT_ROOT}/sweep_status.json"
```

**CLI flags accepted:**
- `--parallel N` (default 1): pass-through to `xargs -P N`. N ∈ {1, 2} only (script aborts with helpful error if N ≥ 3 — Assumption A3 guardrail).
- `--epochs M` (default 1000): override for emergency reruns at a different epoch count.
- `--dry-run`: print the list of (pipeline, seed) pairs that would run, then exit.

**Resume detection** — for each (pipeline, seed), the pair is considered "complete" iff all five files exist and are non-empty:

```bash
is_complete() {
  local p=$1 s=$2
  local d="${OUT_ROOT}/runs/${p}/${s}"
  [[ -s "${d}/config.yaml" \
     && -s "${d}/checkpoint.pt" \
     && -s "${d}/samples.npy" \
     && -s "${d}/metrics.json" \
     && -s "${d}/inverse_kwargs.npz" ]]
}
```

**Status writer** — append to `sweep_status.json` after each pair (parseable, atomic via tmp-file rename):

```bash
# sweep_status.json schema:
# {
#   "started_at": "2026-05-15T12:00:00Z",
#   "epochs": 1000,
#   "parallel": 2,
#   "runs": [
#     {"pipeline": "A", "seed": 42, "status": "complete",
#      "started_at": "...", "ended_at": "...", "wall_seconds": 10800,
#      "return_code": 0, "skipped_already_done": false}
#   ],
#   "all_complete": false,
#   "completed_count": 0,
#   "total_count": 15
# }
```

Use a small Python helper (call from within the bash script via `python3 - <<'EOF' ... EOF` heredoc) to update the JSON atomically — json mutation is unreliable in pure bash.

**Sequential mode (`--parallel 1`, default):**

```bash
for p in $PIPELINES; do
  for s in $SEEDS; do
    if is_complete "$p" "$s"; then
      record_status "$p" "$s" complete --skipped
      continue
    fi
    record_status "$p" "$s" running
    start=$(date +%s)
    python -m revision.run_ablation --pipeline "$p" --seed "$s" --epochs "$EPOCHS" \
        > "${OUT_ROOT}/runs/${p}/${s}_stdout.log" 2>&1
    rc=$?
    end=$(date +%s)
    if [[ $rc -eq 0 ]] && is_complete "$p" "$s"; then
      record_status "$p" "$s" complete --rc $rc --wall $((end - start))
    else
      record_status "$p" "$s" failed --rc $rc --wall $((end - start))
      echo "FAILED: pipeline=$p seed=$s rc=$rc" >&2
      # Do NOT abort the sweep on failure — continue and let the human investigate
      # which pair(s) failed at the end (re-running the sweep retries failed pairs).
    fi
  done
done
```

**Parallel mode (`--parallel 2`):**

```bash
# Build the work-list of (pipeline, seed) pairs that need to run:
WORKLIST=$(mktemp)
for p in $PIPELINES; do
  for s in $SEEDS; do
    if ! is_complete "$p" "$s"; then
      echo "$p $s" >> "$WORKLIST"
    fi
  done
done

# Use xargs -P 2 to dispatch up to 2 simultaneous python processes
# (RESEARCH Pitfall 4: never multiprocessing.Pool; xargs spawns separate
# OS processes so numpy global state is per-process).
cat "$WORKLIST" | xargs -P 2 -L 1 bash -c '
  p=$0; s=$1
  # ... same is_complete + record_status + python -m revision.run_ablation invocation
  # (factor into a function exported via `export -f` so the subshell can see it)
'
rm -f "$WORKLIST"
```

**Final step** — after the loop completes, recompute `all_complete` and `completed_count` in `sweep_status.json` and print a summary table to stdout:

```
=== Sweep complete ===
Total: 15 | Complete: 15 | Failed: 0 | Skipped (already done): 0
Total wall time: 24h 17m
Per-pipeline mean: A=2.9h, B=3.1h, C=3.0h
```

**Crash recovery** — if a single (pipeline, seed) run fails:
1. The sweep script continues with the remaining pairs (does NOT abort)
2. After sweep completion, inspect `sweep_status.json` for failed pairs
3. Re-invoke `./revision/run_ablation_sweep.sh --parallel 2` — already-complete pairs are skipped, failed pairs retry. Idempotent.

**Crash recovery — sweep itself dies (laptop reboot, etc.):**
1. After reboot, re-attach tmux (`tmux attach -t ablation_sweep`) or restart the sweep
2. The resume logic in Task 2 detects complete pairs and skips them
3. Only the in-progress pair at the time of crash will be retried (its incomplete output is overwritten by the CLI driver's idempotent write)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shell script ↔ filesystem | Standard POSIX file operations; idempotency relies on atomic rename of tmp `sweep_status.json` |
| User session ↔ background sweep | Sweep runs unattended for ~24h; tmux/nohup is the user-facing boundary |
| xargs -P 2 ↔ python processes | Two distinct OS processes; numpy global state is per-process, not shared |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09.1.03-01 | Tampering | Two parallel xargs processes write to `sweep_status.json` simultaneously → corruption | mitigate | Status updates serialized through a small Python helper using `os.rename` (atomic on POSIX). Each xargs child reads-modifies-writes under a brief `flock revision/results/transform_ablation/.status.lock` advisory lock. |
| T-09.1.03-02 | Denial-of-service | Sweep hangs indefinitely on one bad seed (e.g., NaN cascading) | mitigate | Each `python -m revision.run_ablation` invocation is bounded by `train_wgan_gp(num_epochs=1000)` — finite loop. No infinite-wait operations. Per-pair stdout/stderr is logged so a hang is investigable. |
| T-09.1.03-03 | Denial-of-service | Mac thermal throttle under sustained load | mitigate | Sweep script caps `--parallel ≤ 2` (Assumption A3); user is warned in Task 1 checkpoint. |
| T-09.1.03-04 | Information disclosure | n/a | accept | No secrets, no PII. |
| T-09.1.03-05 | Repudiation | Sweep silently overwrites a complete run when re-invoked | mitigate | `is_complete()` check guards every pair — only incomplete pairs are re-run. Sweep status records `skipped_already_done: true` for re-runs of complete pairs. |
| T-09.1.03-06 | Tampering | Numpy global RNG shared across forked workers (Pitfall 4) | mitigate | Sweep uses `xargs -P N`, NOT `multiprocessing.Pool`. Each pair runs in a fresh Python process. Documented in script header comment. |
</threat_model>
